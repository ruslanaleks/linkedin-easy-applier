# Бизнес-задача: Сбор тем из ленты LinkedIn и генерация авторских постов

**Версия:** 0.1 (черновик)
**Дата:** 2026-04-28
**Автор задачи:** Ruslan
**Контекст репозитория:** Chrome-расширение (Manifest V3) `linkedin-easy-applier`, ветка `main`

---

## 1. Цель

Добавить к существующему расширению **второй контур** — производство собственного контента. Расширение должно непрерывно собирать релевантные мне посты из ленты LinkedIn, агрегировать темы, обсуждаемые сообществом за «прошлую» и «текущую» неделю, и помогать мне писать авторские посты на выбранную/сводную тему — с настраиваемым тоном (юмор, серьёзность и др.).

**Существующий контур — авто-вовлечение (лайки/комментарии/фолоу/визиты профилей) — продолжает работать без изменений.** Это базовый инструмент расширения, и он остаётся как есть. Новый функционал (сбор тем + генерация постов) — это дополнение, а не замена.

Второе ключевое изменение: **состояние больше не хранится в `chrome.storage.local`**. Все данные — собранные посты, темы, теги, история генераций, настройки тона, **а также настройки и история работы существующего engagement-контура** — должны жить в **удалённой PostgreSQL базе** на сервере и синхронизироваться с расширением через бэкенд. Это даёт переносимость между устройствами и закрывает дыру с API-ключами LLM в локальном хранилище.

## 2. Текущее состояние (опорная база, что уже работает)

| Компонент | Файл | Что делает |
|---|---|---|
| Скрейпинг постов | [feed/feedScraper.js](feed/feedScraper.js) | Извлекает `id, author, headline, content, reactions, comments, reposts, timestamp, hashtags, article, media, scrapedAt, sessionId` |
| AI-скоринг | [feed/feedScoring.js](feed/feedScoring.js) | Claude API оценивает пост 0–100 по 6 критериям (тематика, глубина, комментарий-потенциал, автор, охват, свежесть). Возвращает action: `like_comment_follow / like_comment / like_only / skip` |
| Категоризация (неявная) | [feed/feedScoring.js](feed/feedScoring.js), [feed/feedUI.js](feed/feedUI.js) | `niches` (список ключевых слов), `hashtagCategories` (FinTech/Payments, AI, Startups, Engineering), `dayOfWeekKeywords` |
| Иерархия авторов | [feed/feedScoring.js](feed/feedScoring.js) | Tier 1/2/3 — приоритет инфлюенсеров |
| Авто-вовлечение | [feed/feedEngagement.js](feed/feedEngagement.js) | Лайки/комменты/фолоу с rate-limit |
| LLM-генерация комментариев | [feed/feedAI.js](feed/feedAI.js) | xAI / DashScope / OpenRouter / Ollama |
| Хранилище | `chrome.storage.local` | Всё локально, без аккаунта, без синхронизации между устройствами |

**Что отсутствует и требуется построить:**

1. Явная маркировка постов мной (👍 «по теме» / 👎 «не по теме» / ⭐ «в коллекцию для поста»).
2. Извлечение и нормализация **тем** из контента поста (не просто хэштегов — а семантических тем: «AI agents в проде», «привлёк seed раунд», «увольнения в Big Tech» и т.п.).
3. Агрегация тем по неделям (текущая / прошлая) с метриками частоты, охвата, тренда.
4. UI для выбора темы (одна / сводная) и генерации поста с ползунками тона.
5. Удалённый бэкенд + Postgres + аккаунты + API между расширением и сервером.

## 3. Скоуп задачи

### 3.1. В скоупе

**Сохраняется как есть (существующий контур engagement):**

- Авто-лайки, авто-комментарии, авто-фолоу через [feed/feedEngagement.js](feed/feedEngagement.js).
- Скрейпинг ленты через [feed/feedScraper.js](feed/feedScraper.js).
- AI-скоринг через [feed/feedScoring.js](feed/feedScoring.js).
- Визиты профилей через [feed/profileVisitor.js](feed/profileVisitor.js).
- Rate-limit, человеческие задержки, фильтры по тирам авторов.

Меняется только то, **где живёт состояние** этих модулей: `feedEngagementSettings`, `feedEngagedPostIds`, `feedEngagementDailyStats`, `feedScoringSettings`, `feedAISettings`, `influencerMonitorState` переезжают на сервер (см. §7.3). Поведение и UX engagement остаются прежними.

**Добавляется (новый контур — сбор тем и генерация постов):**

- Расширение собирает **все посты**, которые скоринг-движок отнёс к моим категориям (текущий порог TBD; первая итерация — `score ≥ 40`, action ≠ `skip`).
- Каждый отобранный пост уезжает на сервер вместе с метаданными и извлечёнными темами.
- Сервер строит «коллекцию тем» с временными окнами (текущая неделя ISO, прошлая неделя ISO).
- UI расширения позволяет:
  - Просматривать собранные темы за неделю (топ-N по частоте/охвату).
  - Выбрать конкретную тему ИЛИ запросить «сводную тему» (LLM сам формулирует мета-тему из агрегата).
  - Запустить генерацию поста с ползунками тона: `serious 0–100`, `humor 0–100`, `personal 0–100`, `provocative 0–100`, `length: short/medium/long`.
  - Принять / отредактировать / отбросить сгенерированный вариант. Все варианты сохраняются на сервере.
- Аутентификация: один пользователь = один аккаунт = свой набор данных. Расширение хранит только токен доступа.

### 3.2. Не в скоупе (этап 1)

- Автопостинг сгенерированного поста в LinkedIn — пока я публикую вручную (copy-paste).
- Командная работа / шаринг тем между аккаунтами.
- Мобильное приложение.
- A/B тестирование тонов (это будет этап 2 после того, как накопится история публикаций и реакций).

## 4. Что собирать (модель данных)

### 4.1. Посты (`posts`)

Расширение поверх текущего скрейпинга (см. [feedScraper.js:915-930](feed/feedScraper.js#L915)) досылает на сервер:

- `external_id` — `post.id` из скрейпера (уникален в рамках LinkedIn)
- `author_name`, `author_headline`, `author_profile_url`
- `author_tier` (если автор в моём списке инфлюенсеров)
- `content` — полный текст
- `language` — `ru` / `en` / др. (определяется аналогично [feedAI.js:197](feed/feedAI.js#L197))
- `posted_at` — нормализованная дата (из `timestamp` "2h", "3d" → ISO)
- `reactions`, `comments`, `reposts` — счётчики на момент скрейпа
- `hashtags[]`, `mentions[]`
- `media` — есть ли картинка/видео/статья + URL статьи
- `score` — итоговый балл [feedScoring.js](feed/feedScoring.js)
- `score_breakdown` — JSON с разбивкой по 6 критериям
- `assigned_categories[]` — одна или несколько из моих категорий (FinTech, AI, Startups, Engineering, ...)
- `relevance_label` — пользовательская метка: `null` / `relevant` / `irrelevant` / `starred`
- `scraped_at`, `scraped_by_session`
- `raw_payload` — JSONB сырого ответа скрейпера (для отладки и пересчёта)

### 4.2. Темы (`topics`)

Тема ≠ хэштег. Тема — это короткая нормализованная фраза, извлечённая LLM из текста поста: «увольнения в Meta», «AI agents в продакшене», «raised seed round $5M», «удалёнка vs офис».

- `id`
- `slug` — нормализованное представление (для дедупа)
- `label` — человекочитаемое имя
- `category` — к какой моей категории относится (опционально, может быть несколько)
- `embedding` — pgvector (для семантического схлопывания дублей)
- `first_seen_at`, `last_seen_at`

### 4.3. Связь постов и тем (`post_topics`)

- `post_id`
- `topic_id`
- `confidence` 0–1 (насколько LLM уверен)
- `extracted_at`

Один пост = N тем. Одна тема = N постов.

### 4.4. Недельная агрегация (`weekly_topic_stats`)

Материализованное представление, обновляемое раз в час:

- `topic_id`
- `iso_year`, `iso_week`
- `posts_count` — сколько постов упомянули тему
- `total_reactions`, `total_comments` — суммарный охват
- `unique_authors` — сколько разных авторов писали об этом
- `tier1_authors_count` — топовые авторы тоже про это пишут?
- `growth_vs_prev_week` — % роста относительно прошлой ISO-недели (ключевой сигнал для меня)

### 4.5. Сгенерированные посты (`generated_posts`)

- `id`, `account_id`
- `topic_id` (или `null` для сводных)
- `mode` — `single_topic` / `aggregated`
- `tone_settings` — JSON `{serious: 30, humor: 70, personal: 50, provocative: 20, length: "short"}`
- `prompt` — финальный промпт, ушедший в LLM
- `model`, `provider` — какой LLM генерил
- `output_text`
- `status` — `draft` / `published` / `discarded` / `edited`
- `my_edited_text` — финальная версия, если я редактировал
- `created_at`, `published_at`

### 4.6. Аккаунты и сессии (`accounts`, `sessions`)

- Стандартная схема: email / OAuth (Google) / API key
- Один аккаунт = один LinkedIn-профиль (на этапе 1)
- В расширении хранится только `access_token` в `chrome.storage.local`

## 5. Извлечение тем из постов

**Триггер:** новый пост попал в БД (либо ретроспективно — джоб для уже сохранённых).

**Алгоритм (этап 1, простой):**

1. Сервер берёт `content` поста.
2. Промпт к LLM: «Извлеки 1–5 тем, обсуждаемых в этом посте. Тема — короткая фраза 2–6 слов. Не дублируй хэштеги. Верни JSON-массив `[{label, confidence}]`».
3. Для каждой темы — посчитать embedding (`text-embedding-3-small` или local).
4. Сматчить с существующими темами через pgvector cosine distance < 0.15 → если есть совпадение, переиспользовать; иначе создать новую.
5. Записать `post_topics`.

**Этап 2 (опционально):** ручная курация — UI для слияния «AI agents in production» и «AI agent productionisation» в одну тему.

## 6. UI расширения (новый экран «Темы и пост»)

Кнопка в floating-панели рядом с существующими `Analyze Feed / Auto Engage / Feed Settings`. Открывает панель:

### 6.1. Вкладка «Темы недели»

- Переключатель: `Эта неделя` / `Прошлая неделя` / `Обе`
- Список топ-20 тем, отсортированных по комбинированному скору (частота × охват × `growth_vs_prev_week`)
- Для каждой темы: лейбл, частота, суммарные реакции, тренд-стрелка, кнопка `Развернуть` (показать посты-источники)
- Чекбоксы для мульти-выбора тем

### 6.2. Вкладка «Сгенерировать пост»

- Режим:
  - `Одна тема` — выбираю одну тему из списка выше
  - `Сводный` — LLM смотрит на ВСЕ выбранные/топовые темы и сам формулирует мета-тему
- Ползунки тона:
  - `Серьёзность` 0–100 (default 40)
  - `Юмор` 0–100 (default 60)
  - `Личное / от первого лица` 0–100 (default 70)
  - `Провокационность` 0–100 (default 20)
  - `Длина`: короткий (~50 слов) / средний (~150) / длинный (~300)
- Поле «дополнительный контекст» — что я хочу донести (опционально, свободный текст)
- Кнопка `Сгенерировать` → вызов сервера → возврат 1–3 вариантов
- Каждый вариант: `Принять` (статус `draft`), `Редактировать` (открыть textarea), `Отбросить`
- Кнопка `Скопировать` для финальной версии

### 6.3. Вкладка «Мои черновики»

- Список `generated_posts` со статусом `draft`/`edited`/`published`
- Возможность отметить «опубликовано» вручную (в этап 1 без интеграции с LinkedIn API)

## 7. Архитектура (бэкенд)

### 7.1. Стек (предложение, обсуждаемо)

- **Backend:** Node.js + NestJS *или* Fastify + TypeScript
- **DB:** PostgreSQL 16 + pgvector
- **Очереди:** BullMQ (Redis) для асинхронной обработки тем/embeddings
- **Auth:** JWT + refresh-токены, опционально Google OAuth
- **Хостинг:** Fly.io / Railway / собственный VPS — TBD
- **Миграции:** Prisma или TypeORM
- **LLM-провайдеры:** реиспользуем пул из [feed/feedAI.js](feed/feedAI.js) — xAI/DashScope/OpenRouter/Ollama, плюс Anthropic для скоринга и извлечения тем

### 7.2. API расширение ↔ сервер (черновой контракт)

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `POST` | `/auth/login` | Логин (email+password или OAuth callback) |
| `POST` | `/auth/refresh` | Обновление токена |
| `GET` | `/me/settings` | Получить пользовательские настройки (заменяет `chrome.storage.local`) |
| `PUT` | `/me/settings` | Сохранить настройки |
| `POST` | `/posts/batch` | Батч-загрузка отскрейпленных постов с расширения (idempotent по `external_id`) |
| `POST` | `/posts/:id/label` | Поставить метку relevant/irrelevant/starred |
| `GET` | `/topics/weekly?week=current\|previous` | Темы недели с агрегатами |
| `POST` | `/generate` | Сгенерировать пост (тело: `mode, topic_ids[], tone_settings, extra_context`) |
| `GET` | `/generated` | Список моих черновиков |
| `PATCH` | `/generated/:id` | Обновить статус/текст |

### 7.3. Миграция текущего состояния

Все ключи `chrome.storage.local` (см. отчёт исследования) переезжают на сервер. **Поведение существующих модулей engagement при этом не меняется** — они так же читают/пишут настройки, просто через серверный API вместо локального хранилища. Для расширения это прозрачная замена.

- `feedScoringSettings` → `accounts.scoring_config` (JSONB)
- `feedAISettings` → `accounts.ai_config` (JSONB)
- `feedEngagementSettings` → `accounts.engagement_config` (JSONB)
- `feedEngagedPostIds` → таблица `engaged_posts (account_id, external_id, action, engaged_at)`
- `feedEngagementDailyStats` → таблица `engagement_stats` с дневной агрегацией
- `feedPostCache` → больше не нужен локально, сервер хранит всё в `posts`
- `lastFeedAnalysis` → `analysis_runs`
- `influencerMonitorState` → отдельная таблица `influencer_monitor`

В расширении остаётся только: токен авторизации + кэш «недавно показанных» данных для оффлайн-чтения (опционально, TTL 1ч).

### 7.4. Безопасность

- HTTPS обязателен.
- API-ключи LLM-провайдеров хранятся **на сервере**, расширение их больше не видит. Сейчас они лежат в `feedAISettings` — это дыра, миграция её закрывает.
- Rate-limit на эндпоинт `/generate` (например, 30 генераций/день/аккаунт) — генерации платные.
- Сырое содержимое постов LinkedIn хранится у меня на сервере → нужен disclaimer в UI (это мои данные, никому не передаются).

## 8. Этапы реализации (предложение)

### MVP (этап 1, ~2–3 недели)

1. Поднять Postgres + минимальный API (NestJS/Fastify + JWT).
2. Схема: `accounts, posts, topics, post_topics, generated_posts, weekly_topic_stats (view)`.
3. Эндпоинт `POST /posts/batch` + клиент в расширении: при каждом скрейпе шлём батч на сервер.
4. Джоб извлечения тем (LLM + embedding + дедуп).
5. UI «Темы недели» (read-only).
6. UI «Сгенерировать пост» с базовыми ползунками + 1 LLM-провайдер (Anthropic или xAI).
7. Перенос `feedAISettings` и `feedScoringSettings` на сервер.

### Этап 2

- Перенос остального состояния (engagement stats, engaged ids).
- Ручное слияние/редактирование тем.
- История публикаций + ручной маркер «опубликовано».
- OAuth Google.

### Этап 3

- Аналитика: какие темы/тоны дали мне лучший engagement (требует, чтобы я отмечал реальные реакции на свои посты).
- Автопостинг (если LinkedIn API позволит без блокировок).

## 9. Открытые вопросы (требуют решения до начала работы)

1. **Как определить, что пост «по моей теме»?** Сейчас порог `score ≥ 40`. Этого достаточно или нужен явный список категорий, которые я хочу собирать?
2. **Какие именно категории закрепить как «мои темы»?** Нужно зафиксировать список (FinTech / AI / Startups / Engineering — или другой?).
3. **Окно «недели»** — ISO-неделя (Пн–Вс) или скользящие 7 дней?
4. **Хостинг** — VPS, Fly.io, Railway? Бюджет на инфру?
5. **LLM для извлечения тем и генерации поста** — единый провайдер или микс? Влияет на стоимость.
6. **Ползунки тона — какой набор финальный?** Предложение в §6.2; нужно подтвердить или скорректировать.
7. **Многоязычность** — генерируем посты только на русском, только на английском, или оба?
8. **Что с уже накопленным локальным состоянием?** Однократная миграция при первом логине или начинаем с чистого листа?
9. **Аутентификация** — email+пароль, magic link, OAuth Google? Что приоритетно?

## 10. Критерии готовности (Definition of Done — этап 1)

- [ ] Залогинившись в расширении, я вижу не менее 50 постов из своей ленты, отнесённых к моим категориям, с темами.
- [ ] У меня есть список топ-20 тем за текущую и прошлую недели.
- [ ] Я могу выбрать одну тему и получить 3 варианта поста с заданным тоном.
- [ ] Я могу выбрать «сводный» режим и получить пост, агрегирующий несколько тем.
- [ ] Все настройки и сохранённые посты переживают переустановку расширения / переход на другой компьютер (потому что лежат на сервере под моим аккаунтом).
- [ ] API-ключи LLM не утекают в расширение.
